## 修掉一个真 bug：brief 的 "Recent sessions" 恒为空（同日）

Rg 问「能不能跨 harness 共享记忆」→ 顺手核了一下，发现 recall 根本没在工作。

**Bug**：`src/hooks/brief.rs::query` 把**相对窗口**（`recall_timeframe` 默认 `7d`）原样放进

hook 漏了这一步。后果：**所有 harness、所有默认 profile 的 SessionStart brief 都看不到

- 修：`after_date.and_then(dateparser::parse_after_date)`（不可解析 = 无界，与参考实现一致）。
- 回归测试：`tests/hook.rs::brief_recalls_a_recent_session_through_the_relative_window`
  （自建 scratch vault，不依赖 fixture）。
- 实测 Rg 的 vault：改前 codex/tact 都空；改后两个 harness 都列出
  `Codex checkpoint - 2026-10-05T04-58-37Z …`。

`["tact_session", "codex_session"]`。理由：vault 是共享的，而 Tact 包本来就保留
`codex_session_id` 兼容字段（把 Codex 写的笔记当一等公民），引擎不召回它们自相矛盾。
`session_note_type` 保持 `tact_session` —— 那是"我们写什么"，不是"我们读什么"。
测试：`tact_brief_recalls_a_codex_written_checkpoint`。

**跨 harness 的真实边界**（回答 Rg 的问题）：
- **共享**：vault（笔记本身）、索引、知识图谱 → 任何 harness 的 `search` / `context` /
  `read_note` / MCP 看到的是同一批笔记。

## 代码 review：三个隐藏 bug（两个已修，一个留决策）

方法：先按「必须归一化才能用的值」这个 bug 类扫（刚踩过的那个），再让 Explore 子代理并行扫

### A. `note_type` 两端都不归一化（**未修，需要决定**）
参考实现在**两个边界**都归一化：
- 写入/建模：`schemas/base.py:245` 的 `note_type: NoteType = "note"`，而
  `NoteType = Annotated[str, BeforeValidator(normalize_note_type), …]` → 每次构造 Entity 都归一化。
- 查询：`schemas/search.py:83-89` 的 `field_validator("note_types")`；MCP 工具
  `mcp/tools/search.py:1004` 也做，而且注释直接点名我们的做法是 bug：
  *"Note types use one snake_case identity at write and query boundaries. **Lowercasing alone
  leaves multiword and camel-case inputs in a separate logical population.**"*

我们两边都没做：`frontmatter.rs:80-88` 取原样，`search/index_rows.rs:119` 写原样，
`search/text.rs:401-411` 只 `LOWER(...) IN (...)`。`normalize_note_type` 只在 `application/schema.rs` 用。

**实测**（临时 vault，`type: Memory Service`）：索引里存的是 `Memory Service`；
`search --type memory_service` → **0 条**，`search --type "Memory Service"` → 1 条。
**和参考实现正好相反**。所有 fixture 的 type 都是规范的（note/project/reference/person）
→ golden 全绿，看不见。

**为什么没修**：要改三处（entity 行、search_index metadata、查询过滤器），而且会改掉索引里
**所有笔记**的 note_type —— 属于要带测试和 spec 一句的独立切片。注意 **parser 和写回必须保持原样**：
实测参考实现的 `EntityParser.parse_file` 返回的是 `'Memory Service'`（原始拼写），
归一化只发生在模型/存储边界，所以不要动 `frontmatter.rs` 的 `type` 值（那会改写用户文件）。

### B. MCP 静默丢弃非法的 `entity_types`（**已修**）
`server.rs` 用 `filter_map(|v| v.parse().ok())` → 非法值消失 → 列表为空 → 落到隐式默认
（entity 行）。实测 `search_notes(entity_types=["observations"])` **返回 entity 行**；
而 CLI 报 `unknown entity type`、`recent_activity` 报 `Invalid type: …` —— 同一个请求三种含义。
修：抽出 `helpers.rs::parse_entity_type_names`（大小写不敏感、报参考实现的文案），
`parse_activity_types` 和 search 共用。

### C. `search_all_projects` 的 page 截断 → panic（**已修**）
`params.page` 是 `u64`，代码 `as u32`：`2^32` → 0，随后 `page - 1` 下溢。
实测（debug 二进制）**直接 panic**：`src/adapters/mcp/server.rs:1428 attempt to subtract with overflow`
—— 请求处理里 panic 会把整个 MCP server 进程带走。release 则回绕成荒谬的 offset。
修：page/page_size 用 `min(u64::from(u32::MAX))` 夹住，offset 用 u64 算再转 usize；
`search_options` 同样从截断改成夹住（原来 page_size=2^32 会变成每页 1 条）。

测试：`tests/mcp_search_filters.rs` 新增两个用例（page 那个在修前会 panic）。

### 顺手核过、确认没问题的
`after_date` 三条调用路径（CLI / MCP / hook）现在都归一化；分页算术（`text.rs`/`vector.rs`/
