# Compatibility Test Strategy & Canonicalization

Reference: `basic_memory` 0.23.2. This doc defines how `auto-memory-rs` proves "same behavior".

## 1. Compatibility definition

For the same (project, corpus, config, query), Rust output must equal reference output on:

- Parsed entities/observations/relations (incl. categories, tags, context).
- Permalinks, file paths, project resolution.
- Search candidates, ranking order, scores within tolerance, pagination.
- Graph traversal and `build_context` JSON/text.
- MCP tool inputs/outputs/errors and CLI outputs.

Exact (no fuzzy): identity of permalinks, order of results, pagination, structure, enums,
error categories. Tolerant: floating scores (documented epsilon below).

## 2. Oracle harness (implemented)

Implemented in `tools/export_reference.py` (see `tools/README.md`). Reference outputs are
generated by the **installed 0.23.2** (see `docs/reference.md`) run offline:

- A pinned fixture vault under `tests/fixtures/…`.
- One reference project registered in a **throwaway config dir** (env override) so the user's
  real `~/.config/basic-memory/` is never mutated.
- Capture per fixture:
  - parsed markdown (CLI/import or DB dump),
  - search results per mode (json),
  - `build_context` json/text,
  - tool/CLI stdout + exit codes,
  - environment snapshot (version, config keys, model id).
- Script: `tools/export_reference.py` — copies the model cache into the work dir, runs the
  reference CLI with `BASIC_MEMORY_CONFIG_DIR` + `HOME` pointed at throwaway dirs, then writes
  `tests/golden/`.
- Isolation: the user's real `~/.config/basic-memory` is never read for state or written to.
- Sandbox note: the reference CLI's Alembic migrations hang inside the Codex sandbox, so the
  harness must run with sandbox escalation. It still only writes to `/tmp` and the repo.

## 4. Canonicalization rules

Before diffing, both sides are canonicalized (policy recorded in `tests/golden/reference-env.json`):

- `external_id` (UUID) → `<uuid>`; ISO timestamps (including `created_at`/`updated_at`/
  `generated_at`) → `<timestamp>`.
- Numeric DB ids (`id`, `entity_id`, `observation_id`, `relation_id`, `from_entity_id`,
  `to_entity_id`, `from_id`, `to_id`) → `<field_name>`; these are **not** part of the contract.
- `permalink`, `external_id` (as a value), titles, ordering, and error text remain comparable.
- Score floats: compare with `abs(a-b) <= 1e-6` OR normalize relative to page max when the
  reference itself is scale-dependent. Default epsilon: `1e-6` [decision needed].
- Ordering: rank order must match exactly; tie-breaking rules pinned by fixture.
- Text markdown outputs: compare after trailing-whitespace normalization only.
- **Renamed product surface** (`tests/common/mod.rs::canonicalize_renames`): the corpus is a
  faithful capture of `basic-memory` 0.23.2 and is never edited for this, but this port ships
  its own identity, so a handful of user-visible phrases differ and are mapped back before
  comparing — the diagnostics title, the `create_memory_project`/`delete_project` tool
  descriptions, the activity/search guidance that names the product, the CLI binary named in
  the schema guidance (`auto-memory status`, `auto-memory reindex`), and the binary named in
  the constrained-server project hints (`auto-memory project add|remove`). The mapping is a
  table of whole phrases, so it cannot silently swallow an unrelated difference: everything
  else in a payload still has to match the reference character for character. Adding
  `project add|remove` to the CLI is what turned the last two entries from *divergences* into
  renames — a message that names a command has to name one that exists.
- **Corpus time is pinned, not inherited.** Two surfaces derive from file mtimes
  (`list_directory`'s timestamp column and `updated_desc` ordering, `recent_activity`'s
  recency list) and two windows are wall-clock relative (`context_golden`'s `since_days`,
  the `1d` recency case). `tests/common::copy_fixture_vault` restores the captured mtimes
  from `tests/golden/index/graph-rows.json`, and the two windows are anchored to instants
  recorded in the corpus, so the captures reproduce on a fresh clone and do not expire.
  See `docs/release-checklist.md` §2.

## 4b. Generated corpus (Phase 1 status)

`tests/golden/` contains 52 files: `parse/` (entities/observations/relations),
`index/search-index.json`, 16 search cases (incl. vector + hybrid), 6 context JSON cases,
2 context text cases, CLI status, 3 error cases, the normalized vault, plus
`manifest.json` and `reference-env.json`. Regeneration is one command
(`python3 tools/export_reference.py`) and diffs are contract changes.

## 5. Fixture coverage must-dos

- Every core algorithm + every bug regression.
- CJK/mixed-language note, query, permalink.
- Unresolved wikilink then target created later.
- Duplicate titles across folders.
- Empty vault; malformed YAML; malformed relation lines.
- Multi-project isolation + cross-project search opt-in.
- move/rename/delete and permalink update behavior.
- FTS boolean/phrase/prefix/empty/invalid queries.
- vector threshold edges (similarity near 0.55); hybrid single/dual-source rows.
- build_context bounds and cycles.
- MCP tool happy paths + errors + not-found formatting.

## 6. Rust gate commands

`cargo fmt --check`, `clippy -D warnings`, `cargo test`, doc tests, and a
`cargo test --test compatibility` that runs only when `reference-env.json`/golden present.
CI must run offline-capable subset; full golden suite runs with the reference harness enabled.
