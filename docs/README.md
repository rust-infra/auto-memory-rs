reference implementation, idiomatic Rust internally, Obsidian as the manual management UI.

End-to-end parity: `tests/vector_golden.rs` reproduces both `search/vector-local-index.json` and `search/hybrid-rust.json` through the stored index, `tests/cli_golden.rs` does the same through the CLI, and `tests/embedding_runtime.rs` checks the live runtime against the captured reference vectors. The default-off reranker and the vector-leg filter set are covered by Phase 8c and Phase 15b below.

Timestamp/indexing parity (frontmatter `created`/`modified`, relation insertion order) landed with it — see `reference.md` §6e.
- Phase 10 (note mutation): **done for the local core** — `src/markdown/serialize.rs` (reference frontmatter writer: order-preserving merge, PyYAML block style/quoting, `---\n<yaml>---\n\n<body.strip()>`, malformed frontmatter refused, atomic write) verified byte-for-byte against the reference-normalized vault; `src/markdown/edit.rs` ports every edit operation (`append`, `prepend`, `find_replace`, `replace_section`, `insert_before/after_section`, plus `_merge_metadata_into_markdown`), verified against a captured 22-case reference table including exact error messages; `src/application/note.rs` (`NoteService`) does read/write/edit/move/delete with overwrite protection and automatic reindexing. The CLI/MCP surfaces and the write-path goldens landed in Phase 11d below.
- Phase 11 (stdio MCP server): **done for the local core** — `src/adapters/mcp/server.rs` speaks newline-delimited JSON-RPC 2.0 on stdout (`initialize`, `notifications/initialized`, `ping`, `tools/list`, `tools/call`) with diagnostics on stderr, and exposes 20 tools (15 note/search/graph/navigation/activity/project tools, the three schema tools, and the two ChatGPT adapters): the note family (`write_note`, `read_note`, `view_note`, `read_content`, `edit_note`, `move_note`, `delete_note`), search (`search_notes` plus the `search`/`fetch` ChatGPT adapters, gated on the `initialize` `clientInfo`), graph (`build_context`), navigation (`list_directory`), activity (`recent_activity`), projects (`list_memory_projects`, `create_memory_project`, `delete_project`), and `auto_memory_diagnostics`; CLI `mcp --vault … --index …`. `src/application/directory.rs` ports `DirectoryService.list_directory` (prefix query, tree build, depth/glob collection, the four sort orders, bounded pages with `children: []`), `src/application/activity.rs` ports `build_context` without a `memory_url` (recency search by `updated_at DESC`, shared traversal/hydration, guide-laden text output), and `read_note` follows the reference's text default plus its resolution → title → related-results → not-found chain. `tools/dump_reference_mcp.py` captures real reference responses into `tests/golden/mcp/responses.json` (25 frames); `tests/mcp_golden.rs` replays every text surface character-for-character and every JSON payload field-for-field. Every reference tool except `list_workspaces` is now exposed (Web/Cloud surfaces stay out of scope).
- Phase 11e (Streamable HTTP MCP transport): **done** — `auto-memory mcp --http [--host HOST] [--port PORT] [--path PATH]` serves the same session over the spec's Streamable HTTP transport, built on the official `rmcp` SDK (`transport-streamable-http-server`) with `axum` as the listener — sessions, `Mcp-Session-Id`, SSE framing and content negotiation are the SDK's, not hand-rolled. The tool surface is the *same* `McpServer::call_tool` / `advertised_tools` the stdio transport uses (so the two cannot drift, `--read-only` included), one embedding/reranker runtime is shared by both transports, and `initialize` reports the same protocol version and server name over either. `tests/mcp_http.rs` drives a real session over a hand-written HTTP/1.1 client (session header, `tools/list`, `tools/call`, read-only refusal) and asserts the HTTP tool list equals the stdio one.
- Phase 12–13 (schema / Picoschema core + tool surface): **done** — `src/schema/` ports `basic_memory.picoschema` in five modules: `parser` (field keys with `?`/`(array)`/`(enum)`/`(object)` modifiers and descriptions containing commas/parens/brackets, enum values from a YAML list or a quoted `[a, b], description` string, reference-exact `ValueError` texts), `resolver` (inline → explicit reference → implicit by `type` → none), `validator` (field → observation category or relation type, `present`/`missing`/`enum_mismatch`, unmatched content reported but never failing, `warn` vs `strict`, plus `settings.frontmatter` keys) and `diff` (new/dropped fields + cardinality changes); `inference` counts presence once per note, infers array-ness above half multi-occurrence, and walks each note's categories in first-appearance order before the global `most_common`. `tools/dump_reference_picoschema.py` captures 38 pure-function cases into `tests/golden/schema/picoschema.json`; `tests/schema_golden.rs` (6 tests) replays them including key-order assertions (`serde_json` now uses `preserve_order` — schema mappings are ordered data). The tool surface sits above that: `src/schema/report.rs` (pydantic-equivalent report models), `src/application/schema.rs` (router report assembly, including the file-beats-index schema read and the identifier resolution chain), `src/application/schema_text.rs` (report and guidance renderers) and `src/application/schema_tools.rs` (the guard chain shared by MCP and CLI). CLI: `auto-memory schema validate|infer|diff` prints the same payload as the reference `bm tool schema-*`, byte for byte. `tools/dump_reference_schema_mcp.py` captures three vaults (schema / no-schema / broken-schema) into `tests/golden/mcp/schema.json` — 30 MCP frames plus 14 CLI runs — and `tests/schema_mcp_golden.rs` (2 tests) + `tests/schema_cli_golden.rs` (1 test) replay them. Two parity bugs surfaced there and were fixed: non-`str` tool results must be *compact* JSON, and per-note field order is first-appearance, not count order.
- Phase 14 (Obsidian compatibility and recovery): **done** — `tests/obsidian_compatibility.rs` (6 tests) drives the Obsidian-facing paths against a temp vault: an atomic save (temp file + rename) keeps the entity id, permalink, and `created_at` while the checksum changes, both through `VaultWatcher` directly and through a real `notify` loop; `.obsidian/` and `.basic-memory/` never reach the queue or the index (reconcile included); a wikilink to a note that does not exist yet stays unresolved and resolves when the target is created (the relation search row gains its target permalink at that point); a file-explorer rename keeps the permalink and the incoming links; deleting a note drops its observations, search rows, and cascaded link rows, and a full rebuild restores the stranded link as unresolved. `docs/usage.md` documents install, Obsidian setup, indexing, MCP setup, and recovery.
- Phase 15 (hardening and release, first + second slice): **done for the local core** — `tests/hardening.rs` (4 tests) pins path containment (an identifier or path with `..` can no longer read, edit, delete, or move a file outside the vault; absolute-looking paths resolve project-relative), malformed-UTF-8 tolerance (an undecodable note is skipped while its neighbours index normally), and a dependency-free round-trip property (writing a parsed note twice is byte-stable across 24 generated bodies). The containment test was verified to fail without its fix. `tests/benchmarks.rs` adds three opt-in benchmarks (full vs incremental indexing, search latency percentiles, chunking throughput) that print numbers and assert only loose sanity floors. `tools/smoke.py` is the offline end-to-end gate: it builds with `--offline`, indexes a throwaway vault, runs `status`/`search`/`context`/`schema`, drives the MCP server over stdio, deletes the index, rebuilds, and hashes the vault before and after to prove indexing never rewrites user files. `cargo doc --no-deps` builds clean, `docs/usage.md` documents install/Obsidian/MCP/recovery, and `docs/release-checklist.md` collects the gates, evidence, smoke commands, and parked work.
- Phase 15b (remaining parity items — semantic-leg filters and search-bound semantics): **done** — the vector leg now applies row filters the way the reference does: the FTS half of hybrid carries them natively, and the vector half intersects its ranked candidates with a filter-only scan (`VECTOR_FILTER_SCAN_LIMIT` = 50000, keyed on `(type, id)`), covered by captured `--type`/`--entity-type`/`--tag`/`--status`/`--category` queries in `tests/vector_golden.rs` and `tests/cli_golden.rs`. Two further divergences surfaced while capturing those cases and are fixed: a category filter without `entity_types` must default to **observation** rows (`search::default_entity_types`), and `search`'s `after_date` goes through `dateparser` semantics rather than the timeframe parser the context tools use — naive local time compared as UTC, so the bound is shifted by the UTC offset (`src/domain/dateparser.rs`, unit-tested, with absolute-date goldens). The MCP `search_notes` tool now honours `entity_types`, `status`, `metadata_filters` (with the `note_type` → `type` alias) and `after_date`, verified against the same goldens in `tests/mcp_search_filters.rs`. Regenerating the corpus also showed that re-capture is *not* byte-identical (reference id order + ~1.2e-4 semantic float drift); the semantic score envelope is now 5e-4 with ranking and `matched_chunk` still exact, and `docs/release-checklist.md` says what drift is expected.
- Phase 11c (`search_notes` surface — output format, search types, semantic floor): **done** — `search_notes` now follows the reference end to end. `output_format` defaults to `text` and renders `_format_search_markdown` (result blocks plus a pagination footer), the `No results found …` line for a miss, and `# No Search Criteria` for an empty request; `search_type` maps the query onto `text`/`title`/`permalink` (the latter two *clear* the text field, because an FTS5 OR group ANDed with another `MATCH` is a SQLite error) or onto the `vector`/`semantic`/`hybrid` retrieval modes; an unknown type returns the generic `# Search Failed` guidance naming the valid options, and a semantic request without a runtime returns the `Semantic Search Disabled` guidance instead of silently running a text search. The server can now attach a runtime (`auto-memory mcp --embedding-fixture/--model-cache/--onnx-runtime`), so `search_type="vector"` really ranks against the vector index. `tools/dump_reference_search_mcp.py` captures all nine branches into `tests/golden/mcp/search-types.json`, replayed by `tests/mcp_search_types_golden.rs` (4 tests, including a semantic run with an attached runtime).
- Phase 11d (note-tool surfaces: write/edit/delete/move): **done** — the four note-write tools now match the reference's upsert-shaped surface. `write_note` merges `note_type`/`tags` into the frontmatter (content frontmatter still wins), writes a plain body verbatim but trims one that arrived with frontmatter, blocks an overwrite with the reference's `action: conflict` / `NOTE_ALREADY_EXISTS` payload, refuses a directory outside the project with `SECURITY_VALIDATION_ERROR` (treating `/` as the project root), and answers `{title, permalink, file_path, checksum, action}` plus the `# Created note` summary. `edit_note` is now an upsert (a missing identifier creates the note and reports `fileCreated: true`) with the reference's `{…, operation, fileCreated}` payload and `# Edited note (<op>)` summary. `delete_note` and `move_note` gained their `is_directory` variants — directory summaries, `DESTINATION_FOLDER_NOT_FOR_DIRECTORIES`, `DESTINATION_SAME_AS_SOURCE`, `Entity not found` — and a move now rewrites the destination with the entity's identity, exactly as the reference does. `read_note`'s JSON miss payload also gained the reference's `{title, permalink, file_path}` suggestion shape. `tools/dump_reference_note_mcp.py` captures the whole surface (36 frames) plus the resulting vault files into `tests/golden/mcp/note-tools.json`; `tests/mcp_note_tools_golden.rs` replays every frame byte-for-byte and every file. One deliberate divergence is pinned there: the reference's MCP write path leaves duplicate `search_index` rows, which this port does not reproduce.
- Phase 8c (cross-encoder reranker): **done** — the last config-gated search feature. `src/runtime/rerank.rs` loads the reference model (`jinaai/jina-reranker-v1-tiny-en`) through fastembed's user-defined rerank model and squashes each logit with the reference's clamped sigmoid; `src/search/rerank.rs` ports the flow (fixed pool of `reranker_candidates` from the stable order, documents built as `body + "\n" + title` truncated to 2000 chars, scores replacing the retrieval score, tail demoted to `floor / (index + 2)`, page sliced after reranking, candidate budget `max(semantic_vector_k, candidates * 4) + tail * 10`). It stays **off by default**, matching the reference; the CLI/MCP gain `--reranker`, `--reranker-candidates`, `--reranker-max-chars` and `--reranker-fixture`. `tools/dump_reference_rerank.py` captures four reranked searches into `tests/golden/search/rerank-*.json`; `tests/rerank_golden.rs` replays the flow with a fixture provider whose keys are the document texts, and separately loads the real ONNX model and reproduces the reference's reranked page (verified here with `AUTO_MEMORY_MODEL_CACHE=/tmp/am-model-cache`; the test skips where the model is not installed).
- Completion audit (2026-09-11): every phase in the execution plan is done, and the whole corpus was regenerated from the reference one more time to prove the tests are not passing against stale captures. That regeneration touched 27 files, all inside the known run-dependent categories — concurrent-index id order (`context/**`, `index/graph-rows.json`, `index/search-index.json`, no-query search order), semantic float drift (the `vector-*`/`hybrid-*` scores moved by up to 1.21e-4, inside the 5e-4 envelope), and run metadata (`manifest.json`, `reference-env.json`) — and the full suite stayed green against it. The Phase 15 checklist's last two items are also in place: `tests/properties.rs` (parser / permalink / traversal invariants over generated inputs, with the traversal's uniqueness checked per `(type, id, root_id)` because that is the reference's own `GROUP BY`) and `tests/storage_migration.rs` (schema creation, version-row repair, idempotent migration). The audit also closed the last documented "known gap": `entity.created_at` is now the row's insert time (`tests/index_timestamps.rs`), matching a direct reference measurement where the file mtime was 2.5 s older than the stamped `created_at` — 208 tests, 3 ignored benchmarks. What is intentionally *not* here: `vec0` storage (accepted internal difference — BLOB tables plus Rust scoring, results verified equal), the reference CLI's `bm inspect` retrieval diagnostics, and the Web/Cloud surfaces (`list_workspaces`). See `docs/usage.md` §8 and `docs/release-checklist.md` §6.

- Note: the reference does **not** stem `content_stems`; it concatenates text variants. CJK works through the `unicode61` tokenizer plus variant splitting, which our implementation reproduces.
- Productization pass (2026-09-19) — the repository went from "finished core" to "installable":
  - **The golden corpus is hermetic.** Two `list_directory`/`recent_activity` captures and the
    traversal replay derived from file mtimes and from the wall clock, so they failed on any
    fresh clone and expired a few days after each capture. `tests/common::copy_fixture_vault`
    restores the captured mtimes from `tests/golden/index/graph-rows.json`, and the two
    wall-clock windows are anchored to instants recorded in the corpus. `cargo test` is green on
    39 targets with no known failures (was 3).
  - **The constrained-server project hints became renames instead of divergences**, because
    `auto-memory project add|remove` now exist. `project add` registers *and* indexes,
    `project list` reports counts, `project remove` drops the derived rows (including the FTS
    rows, which have no foreign key to cascade them) and leaves the vault untouched.
  - **`auto-memory doctor`** reports the index, schema version, projects, vault, and the two
    optional semantic-search pieces (ONNX Runtime, model cache), printing either the path it
    chose or the locations it searched; `--json` plus a meaningful exit code. It is read-only:
    a missing index is a warning, and the command never creates the file it is inspecting.
  - **The ONNX Runtime search was rebuilt.** It used to hardcode one interpreter
    (`.../basic-memory/lib/python3.14/...`) and one machine-specific directory, so it silently
    stopped finding the library. It now globs the installed interpreters and searches beside
    the executable, with `ORT_DYLIB_PATH` as the override. The model cache gained a neutral
    fallback (`~/.cache/auto-memory/models`) and `AUTO_MEMORY_MODEL_CACHE`.
  - **Distribution**: `LICENSE` (the full AGPL-3.0 text) and `docs/licensing.md` (the

## Errata

- `auto-memory-rs-spec.md` §4 suggested `.basic-memory/index.sqlite3` inside the vault. The
  reference 0.23.2 stores the derived SQLite index in the **app config dir**
  (`~/.config/basic-memory/memory.db`); a vault only holds markdown + `.basic-memory/config.json`.
  See `reference.md` §5. Whether `auto-memory-rs` mirrors this or deviates is open decision #1 in
  `compatibility-spec.md` §7.
