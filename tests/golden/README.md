`../reference-env.json` for the pinned environment and canonicalization policy.

## Canonicalization

- UUIDs → `<uuid>`; ISO timestamps → `<timestamp>`.
- Numeric DB ids (`entity_id`, `relation_id`, `observation_id`, …) → `<field_name>`.
- Work/repo paths → `<work>` / `<repo>`.
- Checksums and scores are kept verbatim; score comparison uses a documented epsilon.

Numeric DB ids are **not** part of the compatibility contract. Compare permalinks,
`external_id`, titles, ordering, scores (epsilon), and error output instead.

A second, smaller exemption: this port ships its own name, so a handful of user-visible
phrases (the diagnostics title, two tool descriptions, the activity/search guidance that names
the product, and the CLI binary named in the schema guidance) are mapped back to the
reference's wording by `tests/common/mod.rs::canonicalize_renames` before comparing. The
corpus itself is never edited for this — it stays reproducible from `tools/export_reference.py`.

One exception is worth naming: the reference assigns ids while indexing files
**concurrently**, so its id order differs between runs. For `build_context` that changes the
`max_related` cut and hence the tail of `related_results`. `index/graph-rows.json` +
`context/find-related.json` exist so the traversal can be replayed against the reference's own
ids (see `tests/context_golden.rs::find_related_replays_the_reference_traversal`).

## Verified reference behaviors (from this corpus)

- `permalinks_include_project` defaults to **true** → generated permalinks look like
  `oracle/notes/simple`; explicit frontmatter `permalink` is kept verbatim.
- `ensure_frontmatter_on_sync` defaults to **true** → files without frontmatter are rewritten
  with `title`/`type`/`permalink`; the post-sync result is in `golden/vault/`.
- A file with malformed YAML frontmatter is **skipped** (parser warns, batch normalization
  fails); it does not appear in `parse/entities.json`.
- Observation category defaults to `note`; task markers, transcript timecodes, blockquote
  callouts, markdown links, and wikilink-only lines are not observations.
- Prose wikilinks become `links_to` relations; quoted multi-word labels are preserved.
- Schema tools: report payloads drop `null` fields but keep empty lists; all-types validation
  reports canonical note types in `type_summaries`; a malformed schema produces the tool's
  "Failed" template carrying the parser's message; the CLI JSON surface is
  `json.dumps(indent=2, ensure_ascii=True)` (see `docs/reference.md` §6k).
- `search`/`fetch` answer differently by client identity: a non-OpenAI client gets an
  "Unsupported MCP client" payload, `openai-mcp` gets results. Their result frame holds a
  *content list* whose text surface is compact JSON (see `docs/reference.md` §6i).
- A strict query that matches nothing retries as an OR of prefixed words, but only when
  `relaxed_query_words` allows it: three or more word tokens, no numeric token, no quotes or
  boolean operators, and stopwords pruned (see `docs/reference.md` §6d).

## Regenerating

```bash
python3 tools/export_reference.py       # requires reference CLI (+ model cache for vectors)
python3 tools/dump_reference_mcp.py     # requires reference CLI; drives `basic-memory mcp`
~/.local/share/uv/tools/basic-memory/bin/python tools/dump_reference_picoschema.py
```

The harness also shells out to `tools/dump_reference_graph.py` and
`tools/dump_reference_context_text.py` with the reference interpreter; override its location
with `BASIC_MEMORY_ORACLE_PYTHON` (default
`~/.local/share/uv/tools/basic-memory/bin/python`).

Review the diff before committing: golden changes are contract changes.
